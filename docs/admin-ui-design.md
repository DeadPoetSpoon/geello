# Geello 内置管理界面设计（v1）

设计日期：2026-11-22。状态：**v1 已实施，自动化与实机验证范围见第 11 节**。

本文固化已确认的管理范围、交互、服务集成、接口增量和验收标准，作为后续实现依据。
原设计要求保留作为验收依据；已实施边界与尚未完成的验收项另行标注，不能把设计要求当成
全部验证通过的证明。部署和操作说明见 [内置管理台使用与部署](admin-ui.md)。

## 1. 已确认的目标与约束

| 项目 | 决策 |
| --- | --- |
| 使用者 | 能管理地理数据和发布配置的 Geello 运维人员、地图制作者；不是公开终端用户 |
| 服务 | Geello 自身的 Rust/Axum 服务同时提供页面、静态资源、管理 API 和地图服务 |
| 前端 | 原生 HTML、CSS、浏览器 JavaScript 模块，不使用前端框架、组件库、样式库或 Node 构建链 |
| 地图 | 使用固定版本的 OpenLayers（OL），加载 Geello 的正式发布服务 |
| 管理范围 | 数据集、字体、样式、地图、动画，以及异步任务和只读服务状态 |
| 配置编辑 | 表单辅助 + TOML；地图常用配置表单化，复杂样式、动画提供模板与文本编辑 |
| 草稿 | 编辑内容仅在当前页面会话内保留；不新增服务器草稿或未保存配置的渲染接口 |
| 安全 | 沿用反向代理认证；同时保护页面和管理 API，不新增账号、会话或权限系统 |
| 交付顺序 | 先形成本文，用户确认“按照文档实现”后再开发界面和接口 |
| 数据 | 测试下载、运行数据、截图和报告放在现有 Git 忽略的 `assets/test/` 下 |

第一版不包含：完整图形化样式设计器、在线要素编辑、文件管理器、任意 URL 数据抓取、
多用户协同、版本回滚、实时动画播放控制台、运行时配置修改、重启、缓存清空或存储迁移。
资源本身仍沿用现有不可变版本、依赖校验、资源预算及 CPU/GPU 行为，不由页面另造一套规则。

## 2. 现状与复用边界

以下为设计时的基础能力盘点，不是实施后的最新清单；增量实现见第 11 节。

健康检查中的内存核算不等于进程 RSS 或显存；缓存计数是进程内计数，不作为持久业务统计。

## 3. 信息架构与视觉规范

### 3.1 页面导航

管理入口为 `/admin/`，使用 Hash 导航。资源 ID 在 Hash 中编码，不能拼接未经编码的路径。

| 导航 | 页面地址示例 | 主要内容 |
| --- | --- | --- |
| 概览 | `/admin/#/overview` | 实际渲染后端、健康状态、资源总数、核算内存、缓存指标、任务摘要 |
| 数据集 | `/admin/#/resources/dataset` | 搜索、分页、上传/替换、外部注册、CRS 与源解释、依赖和生命周期 |
| 字体 | `/admin/#/resources/font` | 字体上传、版本、引用关系，通过引用地图检查实际注记效果 |
| 样式 | `/admin/#/resources/style` | 模板、新建/编辑、TOML、引用关系、校验结果 |
| 地图 | `/admin/#/resources/map` | 地图配置、图层顺序、资源绑定、发布、预览入口 |
| 动画 | `/admin/#/resources/animation` | 动画模板、TOML、轨道/目标说明、关联地图 |
| 任务 | `/admin/#/operations` | 状态/目标筛选、分页、任务诊断、继续跟踪 |
| 服务信息 | `/admin/#/service` | 只读能力、容量、后端诊断、协议和 API 文档入口 |
| 资源详情 | `/admin/#/resources/map/open%3Aoverlay` | 基本信息、定义、依赖、版本、操作 |
| 地图预览 | `/admin/#/preview/open%3Aoverlay` | OL 大画布、协议、CRS、时间、请求与加载状态 |

数据集、字体等导航共用资源列表与详情骨架，按类型提供动作；不为每种类型复制一套状态管理。
`/admin` 重定向到相对地址 `./admin/`，保留反向代理挂载前缀；不修改根路径的现有行为。

```text
├────────────┬───────────────────────────────────────────────────────────┤
│ 概览       │ 数据集 / open:countries                     上传 / 新建   │
│ 数据集     ├───────────────────────────────────────────────────────────┤
│ 字体       │ 关键字 [             ]  发布状态 [全部]      刷新         │
│ 样式       ├───────────────────────────────────────────┬───────────────┤
│ 地图       │ 资源、类型、所有权、状态、版本、操作      │ 详情 / 引用   │
│ 动画       │                                           │               │
│ 任务       │                                           │               │
│ 服务信息   │                                    分页   │ 错误 / 诊断   │

```

预览页把列表区替换为地图；窄边栏提供地图、协议和 CRS 选择，底部提供加载和坐标状态。
配置编辑页采用表单与 TOML 双标签，预览作为显式跳转，不在每次输入时发起地图请求。

### 3.3 手写样式和可访问性

- 默认浅色工作区、深色导航、蓝绿色主色；第一版不增加主题切换。
- CSS 自定义属性统一管理：背景 `#f5f7fa`、面板 `#ffffff`、文字 `#172033`、
  导航 `#111827`、主色 `#0f766e`、警告 `#92400e`、危险 `#b91c1c`、边线 `#d9e0e8`。
- 使用系统中英文字体；正文 14px、辅助文字 12px、正文行高 1.5，间距基准 4px。
- 桌面导航宽 216px、顶部高 56px、详情栏宽 360px；1024px 以下详情改为单页，
  768px 以下导航收起，表单单列，列表保留必要的横向滚动。
- 按钮使用“保存并发布”“替换数据”“下线”等动作名称；危险按钮不与主操作使用同色。
- 状态必须同时包含文字和颜色；交互目标至少 40px；所有字段有 label，键盘焦点清晰可见。
- 弹窗管理焦点、支持 Escape 关闭并恢复触发点；后台任务消息使用状态区域，避免重复朗读。
- 本地 SVG 图标配合文字，装饰图标隐藏于辅助技术；不引入图标字体或外部样式。
- OL 必需的官方结构 CSS 属于地图组件依赖，不用于替代管理台手写样式，不修改其许可证。

### 3.4 通用页面状态

列表和详情统一支持：初次加载、空列表、筛选无结果、成功、权限失败、连接失败和容量不足。
显示过期数据时标注“连接已断开，以下为上次结果”，不把旧数据呈现为实时正常状态。
字段级错误留在表单附近，操作级错误显示于页面消息区；错误不可只通过短暂 Toast 呈现。
空目录提供“上传数据集 → 新建样式 → 新建地图”的引导，不自动发布测试资源。

## 4. 资源管理与配置编辑

### 4.1 通用资源列表及详情

列表显示标识、类型、所有权、发布状态和版本摘要。关键字匹配资源 ID，不为未定义标题
或服务端没有提供的创建时间伪造数据。每页默认 `min(20, max-list-items)`，由服务端筛选后分页。
查询及刷新不全量加载所有资源定义到浏览器；大定义只在详情/编辑时使用。

详情包括资源 ID、`published`、`ownership`、源格式、有效 CRS、版本、数据/派生版本、
依赖列表和可选定义。绝对文件路径仅在已认证的管理详情里显示，不能泄露给公开发现页。
正向依赖可直接跳转；反向引用按需遍历有界分页结果，若目录代数变化则提示刷新，
不把不完整扫描当作“无引用”。动作提交仍由服务端再次检查依赖。

### 4.2 各类资源的编辑边界

| 资源 | 首期输入与辅助表单 | 预览方式 |
| --- | --- | --- |
| 数据集 | GeoJSON、Shapefile ZIP、GeoTIFF、既有数据集 TOML；格式、编码、CRS、连续/分类解释；外部注册填写绝对路径 | 选择引用地图；未引用时显式创建地图 |
| 字体 | TTF/OTF/字体集合；替换前展示引用样式 | 通过已发布注记地图检查实际字体，不以浏览器字体替代服务器字体 |
| 样式 | 点/线/面/栅格/注记模板；简单模板的颜色、线宽等常用字段；完整 TOML | 发布后打开引用地图 |
| 地图 | 标识、标题、语言、背景、输出 CRS、矩阵集/缩放范围；图层的数据集、样式、顺序、动画绑定 | 保存并发布后进入 OL 预览 |
| 动画 | 模板、时长摘要、完整 TOML；不构建关键帧时间线设计器 | 通过绑定地图指定 `geello_time` |

资源 ID 创建后不可原地改名；“另存为”必须显式选择新 ID，不能暗中移动其他资源的依赖。
上传原始文件时不进行浏览器重投影或抽稀；解释参数使用现有 `X-Geello-*` 请求头。
外部源注册不是上传，也不是 URL 下载；浏览器不能枚举服务器磁盘，允许目录由服务端判定。
数据集 TOML 保留现有“引用已注册源”等限制，不提供绕过外部源规则的路径输入捷径。

地图 `items` 顺序直接决定服务端叠加顺序。上移、下移和拖动必须同步维护完整 item 对象，
保留 `animation_bindings` 与 `geometry_bindings`。不能将 OL 客户端临时层顺序假称为已保存配置。
辅助选择器只显示合适且已发布的资源，服务端仍执行最终类型、字体、轨道和依赖验证。

### 4.3 表单与 TOML 同步规则

1. 获取服务端保存的 `definition` 和 ETag，原始文本作为编辑基线；没有定义时使用匹配类型的模板。
2. TOML 为完整配置的权威编辑表示，表单只编辑明确支持的字段；解析和序列化复用 Rust 模型。
3. 文本改变后，成功解析才更新表单；解析失败保留文本，不用上次的表单值覆盖错误输入。
4. 表单修改作用于完整解析对象，不重新构造只含可见字段的对象；未知或暂不支持的字段不能静默丢弃。
5. 不经表单修改的文本按原样提交。首次进行表单到 TOML 转换前提示：注释、空白和键顺序可能重排；
   确认后展示生成文本，原文本可在当前会话内恢复。语义保留不等于逐字节保留。
6. 显式“检查配置”只检查语法与既有配置模型；不声称已检查所有目录依赖、字体或渲染结果。
7. 保存执行现有准备与发布，服务端失败仍是最终失败；客户端检查不能替代发布验证。

进入脏页面、切换资源或刷新前提示未保存内容。第一版不把定义、路径或文件存入
localStorage/sessionStorage，不持久化凭证；文件输入不能在刷新后自动恢复，页面必须明确提示。

### 4.4 写入状态与安全确认

```text
编辑 / 已选文件 → 提交中（上传字节进度） → 202（已接受）
                                     → 任务 staging / preparing
                                     → ready：重新读取资源和新 ETag
                                     → failed：保留输入，显示诊断
```

托管上传使用原始文件请求体；使用 XHR 获取上传进度，不把发送完毕当作准备完成。
取消上传不等于取消准备任务：已被接受的任务可能继续执行；不提供虚假的后台取消按钮。
发布失败时旧版本通常继续服务，界面重新读取并确认，不能一律显示为资源已下线。

| 动作 | 页面语义与确认 |
| --- | --- |
| 新建 | `If-None-Match: *`；同名存在则保留输入，提示选择新 ID 或显式进入替换流程 |
| 更新 | 使用进入编辑时读取的 ETag 作 `If-Match`，不能在提交前偷偷刷新 ETag 并覆盖他人修改 |
| 下线 | 保留注册和数据，但正式服务不再可用；显示依赖影响，不自动下线引用方 |
| 重新发布 | 使用当前 ETag 和已注册源重新准备；成功才成为发布状态；外部源仍需通过当前访问校验 |
| 删除记录 | 移除注册记录，托管原始内容进入现有保留机制；不承诺释放磁盘，也不暗示可一键恢复 |
| 删除托管内容 | 单独危险操作；输入完整资源 ID 二次确认；外部所有权不显示此入口，服务端仍必须拒绝 |

版本或引用冲突按当前接口的 `409` 处理，缺少条件为 `428`。界面展示当前服务端版本、
原编辑基线与本地内容，提供“重新读取”或“保留本地内容继续处理”，禁止自动强制重试。
网络在写入时断开显示“结果未确认”，先查任务和资源，再由用户决定是否重试。

## 5. OpenLayers 预览

### 5.1 正式发布内容与服务发现

- 仅预览已发布地图。保存成功后显式刷新来源，不创建隐藏临时地图，不用时间戳无条件绕过缓存。
- 查询地图集合、瓦片矩阵和 tileset 信息，按发布能力决定协议、CRS、矩阵集和缩放范围。
  有 WMTS 能力时默认 WMTS；否则使用 OGC Maps；WMS 作为可选协议。
- 支持当前预览适配器的 EPSG:3857 和 CRS84；其他已发布 CRS 显示为暂不支持的预览选项，
  保留服务链接，不在浏览器擅自引入新的投影依赖。轴序遵守对应协议。
- 有可用范围时定位到服务范围；否则先使用协议合法的世界视图，支持手工 bbox 定位，
  不使用 `open:*`、`preview:*` 的地图专用配置或默认“中国范围”作为通用逻辑。
- 不添加外部在线底图；透明地图显示中性背景。默认不跨矩阵边界绕回。

OL 负责导航、图像展示、请求调度和可选要素检查；服务端样式、字体、动画和 GPU 渲染仍由 Geello 执行。
预览可显示协议、CRS、当前 bbox/缩放、加载与失败数量、最近请求及请求 ID，并提供复制正式服务链接。
图例只根据可用样式给出说明；复杂表达式标记为“以服务渲染为准”，不编造精确图例。
动画仅提供时间输入、应用和前后步进，不默认持续播放或宣称固定帧率。

### 5.2 要素检查与图层操作

仅对声明支持的矢量数据开放 Features/WFS 属性检查；bbox 查询必须有分页和总读取上限。
默认每页最多 100 个、一次检查最多 1000 个要素，并受实际服务限制约束；超过上限提示缩小范围。
选择一个数据集后查询，点选结果展示属性，不实现对任意 WMS 图像的客户端反查或伪造 GetFeatureInfo。
检查结果使用单独、可关闭的 OL 高亮层，不与服务端画面混淆。

地图内图层的开关、样式与顺序在编辑页修改并发布后生效；预览页不提供暗示已保存的临时编辑。
未被地图引用的数据集提供“创建地图”引导，先显式选择样式并发布，再预览。

### 5.3 请求预算与过期处理

管理界面使用一个共享请求调度器，fetch、上传 XHR、OL 图像与瓦片加载都必须经过它：

- 总并发上限为 **2**，预览请求最多占 **1**；只限制本管理台，不能宣称为服务端全局限流。
- 管理写入优先于列表/任务查询，后者优先于未发出的预览请求；不抢占已经发出的请求。
- 待执行请求上限 **64**。预览按当前视图优先，丢弃过期队列项；管理队列满时明确提示稍后重试。
- 相同读请求在途合并。新视图增加 generation，过期响应不再更新 UI，但已发出的请求需完成响应读取
  或确实终止后才归还名额；不能一执行 AbortController 就假设服务器容量已经回收。
- 连续输入只更新本地状态，服务请求由应用动作或稳定视图触发；相同已发布内容正常利用缓存。
- 可见任务每 2 秒最多发一次列表轮询，概览健康每 10 秒一次；隐藏标签暂停新轮询，不重叠补发。
  轮询失败按 2、4、8、16、30 秒退避，成功恢复；显式重试可提前重新查询。
- 写请求不自动重试。渲染 503 不自动无限重试，展示错误、请求 ID 和用户触发的重试入口。
- 未完成上传或已经接受的后台准备可能影响容量；客户端限流不替代后端预算和部署容量验证。

XHR 与 fetch 必须在成功和错误响应上都完成清理。单张瓦片失败只标记对应请求，不能把错误响应当成空白成功图。
可观察到的 JSON、XML 和普通 HTTP 错误分开处理；WMTS 的通用 XML 错误不能推断出准确内部故障。

## 6. 服务集成、部署与安全

### 6.1 页面与资源发布

内置页面放在后续新增的 `src/server/admin/` 资源目录，通过专用 Axum 模块挂入现有服务。
使用编译时嵌入的白名单资源，不提供任意目录文件服务。`server` feature 包含管理台，
`--no-default-features` 的纯库使用不引入服务端或前端依赖。

入口为 `/admin/`；脚本、CSS、SVG、OL 位于 `/admin/assets/`。只允许白名单资源及正确 MIME，
未知路径返回 404，不读取磁盘，不把未知 API 或任意 URL 回退成 HTML。
嵌入资源属于只读静态数据，不复制进渲染缓存或占用渲染队列；静态响应仍参加请求 ID、
服务关闭和有界请求生命周期管理，不通过特殊路由绕开全局容量检查。
HTML 使用 `no-cache`；资源使用内容 ETag 与重验证，正确支持 GET/HEAD/304，不缓存管理 JSON。

OL 沿用已用于示例的 **10.7.0**，不在本工作中升级。后续实现须把官方浏览器发行文件、
许可证及固定 SHA-256 清单纳入可跟踪资源，干净检出即可构建和离线加载。
不得引用当前被忽略的 vendor 目录、开发机绝对路径，或在构建时联网下载。
本设计只锁定版本与交付方式，不把尚未核对的发行文件校验值写成已验证结论。

### 6.2 同源与子路径

前端从页面 `/admin/` URL 推导服务基路径，使用相对路径定位 `admin/v1`、`api`、`health` 及地图路由，
不硬编码 `http://127.0.0.1:3000`、当前域名根路径或 `8080`。
对于发现接口返回的链接，只接受当前服务基路径下的服务链接；按配置的公开基地址映射到同源，
不提供通用 URL 代理，不向第三方自动发送认证请求。协议链接的查询与编码保持不变。

验收必须覆盖 `/admin/` 和 `/prefix/geello/admin/`。反向代理可以剥离前缀转发，但必须为
管理页面、静态资源及 `/admin/v1` 使用一致的认证和挂载策略；TLS 与外部基地址由部署配置决定。

### 6.3 访问保护

- 首期无内置登录页，不把“需要代理认证”误写成“Geello 已提供身份认证”。公开部署须阻止绕过代理直连后端。
- `/admin/`、`/admin/assets/`、`/admin/v1` 均需部署保护；原有公开 OGC 路由保持既有部署策略。
- 客户端使用同源凭证，不保存认证 token，不新增跨域放行。401/403 显示访问受限；
  代理返回登录 HTML 时显示认证可能过期，不能把 HTML 当 JSON 解析失败后无限重试。
- 新增管理写入保护：有 Origin 的浏览器请求必须匹配配置公开基地址的 origin，
  `Sec-Fetch-Site: cross-site` 拒绝；无 Origin 的既有非浏览器客户端保持兼容。
  代理必须保留这些头；此检查不能替代认证，也不声称能识别任意非浏览器来源。
- 保留严格请求方法、媒体类型、条件请求及请求体上限；缺少条件不因来自管理页面而放行。
- 页面采用本地脚本和模块，CSP 默认仅同源；为 OL 的 blob 图像和必要动态样式单独放行，
  不开放任意脚本、内联事件或 `eval`。同时配置 `nosniff`、禁止嵌入、禁止外部表单提交和严格 referrer 策略。
- 资源名、属性、诊断、TOML 和路径使用 `textContent`/表单值输出，不以 `innerHTML` 拼接用户内容。

## 7. 管理接口增量（全部待实现）

以下是第一版采用的接口约定。所有新增 JSON 接口沿用 `application/problem+json`、
`X-Request-Id`、未知/重复查询参数拒绝、容量核算和错误清洗；不修改现有公开 OGC 协议语义。
输入体上限沿用 `max_registry_bytes`，分页上限沿用 `max_list_items`。
实现时同时更新 OpenAPI 生成源、生成文件及契约测试，不能只修改静态 JSON。

### 7.1 资源列表筛选

扩展 `GET /admin/v1/resources`：

- 保留 `offset`、`limit`，新增可选 `kind`、`q`、`published`；`q` 对完整 ID 作 ASCII 不区分大小写的子串匹配，最长 256 字符。
- `kind` 使用既有五种资源类型；`published` 仅接受 `true`/`false`；筛选先于分页。
- 保留响应 `generation`、`resources`，新增 `total`（筛选结果总数）。排序仍为既有资源键顺序。
- 请求在一个目录快照下完成筛选、计数和当前页复制；仅复制当前页，计数不克隆所有定义。
  分页之间 generation 变化时页面提示刷新并回到第一页，不承诺跨请求的固定快照。
- 未传新增参数时保留原行为；OpenAPI 明确新增字段，验证原客户端不依赖严格的旧响应字段集合。

### 7.2 任务列表

新增 `GET /admin/v1/operations`：

- 参数：`offset`、`limit`、可选 `status`、`kind`、`resource_id`；资源 ID 精确匹配，状态使用现有五态。
- 响应：`{ "operations": [Operation], "total": 0 }`，Operation 复用现有单任务结构，不增加虚构进度百分比。
- 按 `operation_id` 逆序确定性排序；不把它承诺为跨重启、系统时钟变化后的精确时间顺序。
  概览的“最近提交”仅使用当前会话的实际提交顺序；已有任务称“任务摘要”。
- 只读取现有内存/持久操作账本，不另建数据库，不新增自动清理策略。已被现有保留策略移除的任务返回 404。
- 单次轮询只查列表；打开详情才查单任务。状态可能在分页之间改变，页面显示当前查询结果而非审计快照。

### 7.3 TOML 辅助接口

新增两个受保护的 POST 接口，`kind` 第一版仅接受 `style`、`map`、`animation`：

| 接口 | JSON 请求 | JSON 成功响应 |
| --- | --- | --- |
| `/admin/v1/configurations/{kind}/parse` | `{ "text": "完整 TOML" }` | `{ "document": { ...完整配置树... } }` |
| `/admin/v1/configurations/{kind}/serialize` | `{ "document": { ...完整配置树... } }` | `{ "text": "TOML", "document": { ...规范化配置树... } }` |

解析首先保留完整 TOML 值树，再调用既有 `parse_style`/`parse_map`/`parse_animation` 校验；
不能仅序列化会忽略未知键的局部 UI 模型。序列化后重新解析验证，模型不接受的内容原样报错。
对于 JSON 无法无损表达的值（例如超出安全整数范围的整数或 TOML 特殊值），拒绝辅助转换并提示
继续文本编辑，不静默舍入、置空或强制转换。原始 TOML 上传行为不因此收紧。
不解析任何客户端传入的文件路径，不创建任务、写目录、发布或渲染。
返回语法/结构诊断，只有解析器可靠提供位置时才显示行列，不伪造字段路径或校验级别。
语法/结构错误采用既有配置错误映射；非法请求 JSON/类型为 400、非法配置为 422、容量拒绝为 503。

### 7.4 重新发布

新增 `POST /admin/v1/resources/{kind}/{id}:publish`，无请求体，必须携带当前强 ETag 的 `If-Match`。
沿用现有 `:unpublish` 动作路径风格；`publish` 和 `unpublish` 应明确分派，不破坏现有路径行为。

服务器读取当前记录和所有权，托管资源从已保留的托管源准备，外部资源重新验证允许目录和源；
准备时复用既有资源限额、工作队列和最终条件提交检查。没有保留源或已删除的资源不能恢复。
返回 `202` 和既有 Operation；成功重新读取资源 ETag，失败保留之前的权威状态。
已发布资源也可显式执行，含义为从已注册源刷新并发布，不作为无副作用请求自动重试。
资源不存在为 404、缺少条件为 428、过期 ETag/依赖冲突为 409，其他准备失败按现有任务诊断呈现。

### 7.5 不改变的既有写入协议

- `PUT .../{id}/content`：原始内容，复用既有 Content-Type 与 `X-Geello-*` 解释头，返回异步任务。
- `PUT .../{id}/source`：既有 SourceSpec JSON，仅注册服务器允许的外部路径。
- `POST .../{id}:unpublish`：条件化下线；不连带下线依赖方。
- `DELETE .../{id}` 与 `DELETE .../{id}/content`：分别删除记录和删除托管内容。
- `GET /admin/v1/operations/{id}`：查询状态，不提供取消或自动重试语义。

以上接口均不增加“以管理员身份忽略预算/依赖/ETag”的通道。
